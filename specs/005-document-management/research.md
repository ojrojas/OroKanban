# Research: Document Management

**Feature**: 005-document-management | **Date**: 2026-09-01 | **Status**: Complete

No `NEEDS CLARIFICATION` remained — all technical choices are informed by `draft/libraries/buildingblocks.md` + constitution Principies IX/XV/XVII/XIX + existing modules `Documents`/`Projects`/`Organization` + prior specs 002/003. **Update 2026-09-01 clarification**: todo documento/versión debe ser escaneado y marcado seguro; contenedor no sirve lectura/descarga si `IsSafe=false` — incorporado en Decisiones 2, 4 y 5 (gate `IsSafe` en `IDocumentAccessPolicy` + `IStorageGateway`).

## Decision 1: Object storage — S3-compatible SDK via Aspire resource (MinIO dev, AWS S3 prod) with hash-key naming, adapter via IStorageGateway

- **Decision**: Binary content is never stored in PostgreSQL. Implement `IStorageGateway { Task<Result<BlobRef>> PutAsync(Stream bytes, ContentHash hash, MimeType mime, CancellationToken ct); Task<Result<Stream>> GetAsync(ContentHash hash, CancellationToken ct); Task<bool> ExistsAsync(ContentHash hash, CancellationToken ct); string CreatePresignedUrl(ContentHash hash, TimeSpan ttl); }` behind `AWSSDK.S3` (prod) + `Minio` SDK (dev). The blob key is `sha256/{hash}.{ext}` (hex 64 chars + mime-derived ext) — deduplication: `PutAsync` checks `ExistsAsync` first and skips upload if present. AppHost adds `builder.AddMinio("objectstorage")` in dev (`WithDataVolume`, `WithReference(postgres).WaitFor`) and maps to `AWS:ServiceURL`/`BucketName` env (`Documents__BucketName`, `Documents__PresignedUrlTtlMinutes=60`). Database stores only `ContentHash` + `Size` + `MimeType`; `Storage` pipeline stage does `PutAsync` + SHA-256 re-hash verification. Presigned URLs are v4, short-lived (15–60 min) or streaming via `IStorageGateway.GetAsync` depending on classification.
- **Rationale**: Satisfies R6 + SPEC-012 at-rest protection + ADR-005-01 (selection via ADR, metadata-only DB). S3 API is the de-facto object-storage contract; `AWSSDK.S3` works against both AWS S3 and MinIO (S3-compatible endpoint). Hash-key naming yields natural deduplication and content-addressability; re-hash at `Storage` stage prevents corruption (SC-008). Aspire resource keeps dev/prod parity.
- **Alternatives considered**: Store `bytea` in Postgres (rejected — violates R6/SPEC-012, blows up DB, no dedup); filesystem volume (rejected — not distributed, violates Aspire orchestration, no presigned URL); Azure Blob SDK (rejected — S3-compatible covers both AWS and MinIO with one SDK, less code; could be swapped via `IStorageGateway` without domain changes).
- **ADR**: ADR-005-01 records provider selection, bucket naming (`orokanban-documents-{env}`), SSE-S3/KMS for at-rest encryption per SPEC-012, and lifecycle rule (no hard purge — soft `Deleted` only).

## Decision 2: Virus/security scan — abstracted ISecurityScanProvider with stub + ClamAV/ICAP adapter, pipeline stage explicit retry + safe-marking gate

- **Decision**: `ISecurityScanProvider { Task<ScanResult> ScanAsync(Stream content, ContentHash hash, CancellationToken ct); }` where `ScanResult { bool IsClean; string? Reason; ScanFailureKind Kind; }` with `Kind=Clean|Infected|Unavailable`. In dev/tests a stub is injected: `FakeScanProvider(result)` configured per test — clean by default, `infected` when hash or name matches fixture, `unavailable` when flag set. Prod adapter can wrap ClamAV (TCP `clamd` via `nClam`-style client) or ICAP service, registered via `Documents.Infrastructure` DI. Pipeline `VirusScan` handler calls `ScanAsync`; `Clean` → marca `DocumentVersion.IsSafe=true`, `ScanStatus=Safe`, `ScannedAt=UtcNow`, `ScannedBy=system`, emite `DocumentVersionMarkedSafe` + `DocumentProcessingStageCompleted` y avanza a `Metadata`; `Infected`→`IsSafe=false`, `ScanStatus=Infected`, `FailedRetryable(reason=Infected)` y nunca procede a `Storage` ni habilita lectura; `Unavailable`→`IsSafe=false`, `FailedRetryable(reason=ScannerUnavailable)` retryable; después de `maxAttempts=3`→`FailedPermanent`. Todos los outcomes emiten `DocumentProcessingFailed`/`StageCompleted` via same-tx outbox, `DocumentStatus` nunca avanza a `Available`, **y `IDocumentAccessPolicy` + `IStorageGateway` deniegan lectura/descarga con `NotSafe` mientras `IsSafe=false` incluso si Golden Rule A/clasificación/grants pasan (clarificación 2026-09-01)**.
- **Rationale**: Satisfies R5 pipeline step, SC-004, Principle XIX; abstraction keeps domain testable without scanner infra (unit via stub), while prod wiring is a single adapter. Explicit retry honors `maxAttempts` and keeps no half-classified documents.
- **Alternatives considered**: Inline scan in HTTP handler (rejected — violates XVII, blocks upload, R5 forbids); 3rd-party SaaS-only coupling (rejected — violates I, no offline testability); no scan (rejected — violates R5/SPEC-012).

## Decision 3: Classification policy — versioned IClassificationPolicy with default Enumeration + org extension table + ruleVersion stamp

- **Decision**: `IClassificationPolicy { Task<(Classification classification, string ruleVersion)> ClassifyAsync(ClassificationContext ctx, CancellationToken ct); IReadOnlyList<ClassificationLevel> AllowedLevels(Guid organizationId); }` where `ClassificationContext { MimeType mime, IReadOnlySet<string> tags, string? documentType, Guid organizationId, string? authorDept }`. Storage: `documents.classification_rules` table (`id`, `organizationId` nullable — null = system default, `version` int/string e.g. `v3`, `effectiveFrom` UTC, `ruleSetJson` jsonb containing `{ defaultLevels: [...], orgExtensions: [...], rules: [{ when: { tag: "finance" }, then: "Restricted"}] }`, `isCurrent` bool). System seeds `Public(1)|Internal(2)|Confidential(3)|Restricted(4)|HighlyRestricted(5)` as `Enumeration` rows; org extensions are inserted per-org (e.g. `TopSecretFinance(101)`) and validated against `ruleSetJson` at `Classify`/`Upload` time. `Document`+`DocumentVersion` store `ruleVersion` (string) taken from the policy at classification execution time — old docs keep `v3` after rule advances to `v4` (SC-005). Pipeline `Classification` stage resolves at execution time, not enqueue time. In-memory cache via `IMemoryCache` keyed by `organizationId→(ruleSet, version)` invalidated on rule update event.
- **Rationale**: Satisfies R1/R3/R5 + FR-002/FR-013 + SC-005 + Principle XV/IX version awareness; org extensions are data, not code; version stamp gives auditability and reproducibility. Pure query side remains testable via stub `FakeClassificationPolicy`.
- **Alternatives**: Hard-coded enum only (rejected — violates R1 org extensions); unversioned classification (rejected — breaks SC-005/history); per-document ad-hoc classification string without policy (rejected — violates VI).

## Decision 4: Pipeline orchestration — DocumentProcessingJob aggregate with ProcessingStage Enumeration + idempotent RabbitMQ handlers + outbox

- **Decision**: `DocumentProcessingJob : AggregateRoot<DocumentProcessingJobId>` with fields `DocumentId`, `DocumentVersionId`, `CurrentStage`, `StageStatuses : Dictionary<ProcessingStage,int status>`, `AttemptCount`, `LastError`, `RuleVersion`, `CreatedAt/UpdatedAt`, `RowVersion`. Stages ordered: `Upload(1)→Validation(2)→VirusScan(3)→Metadata(4)→Classification(5)→Storage(6)→Indexing(7)` as `Enumeration`. Flow: `UploadDocument` handler in one `DocumentsDbContext` transaction persists `Document`+`DocumentVersion`+`DocumentProcessingJob(CurrentStage=Validation, Upload=Succeeded)` + outbox `DocumentUploadedIntegrationEvent` + `DocumentProcessingStartedIntegrationEvent`; `OutboxProcessor` publishes to RabbitMQ topic `document.processing.validation` etc. Each stage has a `BackgroundService` consumer (`IIntegrationEventHandler<DocumentProcessingStageRequestedIntegrationEvent>`) that: (a) loads job with `RowVersion`, (b) sets stage `InProgress`, (c) executes domain logic (validation, scan, metadata extract, classification, storage put+hash verify, indexing event), (d) on success sets `Succeeded` + advances `CurrentStage` + emits `DocumentProcessingStageCompleted` + publishes next stage event, (e) on failure sets `FailedRetryable` + increments `AttemptCount` + emits `DocumentProcessingFailed` + schedules retry with exponential backoff (`2^attempt * 500ms`) via `IEventBus` delay or Polly. All handlers are idempotent: re-executing a `Succeeded` stage is no-op (guard `if job.StageStatuses[stage]==Succeeded return`). `RetryProcessingStage` command resets stage to `Pending` and republishes. No stage ever runs inside the HTTP `UploadDocument` handler (SC-001 enforced by test asserting zero scan/classify invocations in-request).
- **Rationale**: Satisfies R5 + FR-010-012 + XVII + SC-004 + no half-classified documents (DocumentStatus stays `Processing`/`ProcessingFailed` until Storage+Classification both Succeeded). BuildingBlocks outbox + `IEventBus` RabbitMQ topic exchange with publisher confirms + manual ack covers at-least-once + idempotency. Mirrors metrics pipeline triggering pattern already proven in spec 004 research Decision 5.
- **Alternatives**: In-process `BackgroundService` without outbox (rejected — loses messages on crash, violates XVII transactional guarantee); per-stage HTTP call (rejected — blocks request, no resume); single monolithic handler for all stages (rejected — not resumable, failures lose partial progress).

## Decision 5: Access evaluation — pure IDocumentAccessPolicy composing IManagementHierarchy + IProjectMembership + explicit grants + classification ordering + IsSafe gate

- **Decision**: `IDocumentAccessPolicy { Task<AccessDecision> EvaluateAsync(AccessContext ctx, CancellationToken ct); }` where `AccessContext { Guid actorId, Guid tenantId, Document document, DocumentVersion version, Classification classification, bool isSafe, Guid ownerId, Guid organizationId, Guid? projectId, Guid? workItemId, IReadOnlySet<string> actorRoles }` and `AccessDecision { bool Granted; string Reason; }`. Logic (deny-by-default, OR over grants): **(0) `IsSafe==false` (`ScanStatus≠Safe`) → deny `NotSafe` (404-shadow), crea `DocumentAccessEntry(granted=false, reason=NotSafe)` + `DocumentAccessDenied`, no binario/URL, aunque pasos 1-6 pasarían**; luego (1) tenant mismatch → deny 404-shadow; (2) actor is `OwnerId` → grant; (3) `ExplicitGrant` table `documents.document_explicit_grants(documentId, userId, grantedAt)` contains actor → grant; (4) classification clearance: `actorMaxClassification(roles)` is looked up from `Identity` role→classification map (SPEC-002 permission catalog — e.g. `viewer` may read `Public|Internal`, `manager` may read `Confidential`, `restrictedReader` may read `Restricted`, etc.) — if `classification.Level > actorMax` → deny even if hierarchy passes; (5) `IManagementHierarchy.IsInSubtree(ownerId, actorId)` → grant if actor is ancestor/manager of owner; (6) `IProjectMembership.IsMember(projectId, actorId)` → grant if member. Steps 5/6 are OR. All reads are tenant-scoped (`DocumentByTenantSpec`). Denied path creates `DocumentAccessEntry(granted=false)` + `DocumentAccessDenied` event + `audit.authorization.denied` integration; granted path creates `DocumentAccessEntry(granted=true)` + `DocumentAccessed`. `IStorageGateway.GetAsync`/`CreatePresignedUrl` también verifica `IsSafe` antes de tocar el blob. Policy is pure domain (no I/O except injected `IManagementHierarchy`/`IProjectMembership` reads + `IsSafe` value) — unit tests use fakes to exhaust SPEC-013 matrix (5 classifications × 8 actor types = 40 cases) **× 2 estados safe/unsafe**. `GetDocument`/`ListDocumentVersions`/`Download` queries call policy before returning `DocumentResponse`; `GetAccessHistory` checks `document.audit.read` or ownership.
- **Rationale**: Satisfies R4 + FR-007-009 + SC-003/006 + Principles VII/XV/XIX; reuses existing Shared Kernel (`IManagementHierarchy`) and `IProjectMembership` adapter from Projects (read-only projection of `projects.project_members`); classification ordering makes access deterministic; tenant-first avoids enumeration; OR semantics matches spec edge "subtree alone suffices if clearance passes".
- **Alternatives**: DB row-level security only (rejected — not portable, harder to test domain matrix); pre-filter via SQL join only (rejected — leaks policy into query, not pure/testable); separate per-document ACL only (rejected — violates Golden Rule A).

## Decision 6: Immutability & lifecycle — append DocumentVersion + DocumentStatus Enumeration with IBusinessRule transition matrix + soft delete

- **Decision**: `DocumentVersion` is append-only; `Document.Create(name, ...)` creates v1 with `IsPublished=true` only after `Validation` stage succeeds (before that, `DocumentStatus.Draft/Uploaded`). `PublishDocumentVersion(documentId, bytes|metadata)` always inserts a new row: `version = maxVersion+1`, `ContentHash` new SHA-256, `MetadataSnapshot` copied value, `PublishedAt=UtcNow`, `PublishedBy=actor`, `RuleVersion` current; prior version emits `DocumentVersionSuperseded`. Direct mutation guarded by `VersionIsImmutableOncePublishedRule` checked in `DocumentVersion` private setter. `Document.CurrentVersionId` is updated to new version id. `DocumentStatus` (`Draft(1)|Uploaded(2)|Validated(3)|Classified(4)|Indexed(5)|Available(6)|PendingApproval(7)|Approved(8)|ProcessingFailed(9)|Archived(10)|Deleted(11)|RetentionExpired(12)`) transition map enforced by `DocumentStatusTransitionRule : IBusinessRule` via `CheckRule` in `Document.ChangeStatus(target)` — valid edges: `Draft→Uploaded→Validated→Classified→Indexed→Available→PendingApproval→Approved`, `*→ProcessingFailed` (on any stage failure), `ProcessingFailed→Validated` (on retry success), `Available/Classified/PendingApproval/ProcessingFailed→Deleted` (via `DeleteDocument`), `Available→Archived`, any `*→RetentionExpired` (time-based flag, not auto-delete). `DeleteDocument` never `DELETE` rows — sets status `Deleted` + `DeletedAt/By` + emits `DocumentDeleted` via outbox; subsequent reads return `Error.NotFound` to non-auditors (404 shadow) but auditors/history can still query.
- **Rationale**: Satisfies R2 + FR-003/004/006 + SC-002/007 + Principles IX/XIV/VIII; append-only guarantees traceability; transition map makes illegal transitions reject with `Error.BusinessRule`; soft delete preserves audit/history; mirrors Project `Status` pattern from spec 003 but document-specific.
- **Alternatives**: In-place update of version row (rejected — violates IX, SC-002); hard DELETE (rejected — violates FR-004/VIII); event-sourcing for versions (rejected — over-engineering, EF append rows suffice).

## Decision 7: Metadata snapshot — ValueObject with jsonb storage, value-equality, custom bag validation

- **Decision**: `MetadataSnapshot : ValueObject` with components `Author(string? 1–200), Department(string? 1–200), Project(string? 1–200), Tags(IReadOnlySet<string> trimmed/lowercased/1–50/`^[a-z0-9_-]+$`/≤50), DocumentType(Classification-like Enumeration or string 1–100), EffectiveDate(DateTime?), ExpirationDate(DateTime? check Effective <= Expiration), Source(string? 1–200), Confidentiality(string? 1–100), RetentionPolicy VO, CustomMetadata(IReadOnlyDictionary<string,string> key ≤64/value ≤2KB/≤50 entries)`. Stored as `jsonb` column `documents.document_versions.metadata_snapshot` via `OwnsOne` or `HasConversion` to `string` + Npgsql jsonb, plus `EffectiveDate/ExpirationDate` extracted as indexed columns for retention queries. Equality is `GetEqualityComponents()` over all fields (order-independent for Tags/CustomMetadata). Snapshot is copied at `PublishDocumentVersion` time — never live-joined to Project/Author tables. Validation in VO constructor returns `Error.Validation` via `IBusinessRule` in calling aggregate.
- **Rationale**: Satisfies R3 + FR-005 + snapshot semantics + SC-002/006 traceability; jsonb keeps schema flexible for custom bag while preserving queryability; ValueObject equality enables snapshot comparison tests without DB.
- **Alternatives**: Separate `document_metadata` table with live FK (rejected — violates snapshot, would drift when source changes); schemaless EAV (rejected — over-complex); storing custom bag as separate rows (rejected — unnecessary for ≤50 entries).

## Decision 8: Provenance, retention, hash/MIME — ValueObjects with construction invariants

- **Decision**: `ContentHash : ValueObject` (string 64 chars `^[0-9a-f]{64}$`, lowercased SHA-256 computed via `SHA256.HashData`) + helper `ContentHash.FromBytes(bytes)`; `MimeType : ValueObject` (string 1–255, `^[-+.\w]+/[-+.\w]+$`, allow-list `["application/pdf","image/png","image/jpeg","text/plain","application/msword","application/vnd.openxmlformats-officedocument.*","text/csv"]` configurable per org, fallback `application/octet-stream` with warning integration event; `RetentionPolicy : ValueObject { DateTime? RetainUntil, int? RetentionDays, bool LegalHold, bool IsExpired(DateTime now) => !LegalHold && RetainUntil != null && now >= RetainUntil }` with `RetainUntil` computed from `EffectiveDate + RetentionDays` if not explicit; `Provenance { string Source, string OriginalFilename, Guid UploadedBy, DateTime UploadedAt }` embedded in `Document`. All validate at construction; hash verification at `Storage` stage compares computed hash against stored `ContentHash` — mismatch → `FailedRetryable(reason=HashMismatch)`.
- **Rationale**: Satisfies FR-018/020 + hash-key storage integrity (SC-008) + provenance traceability (Final Rule) + retention flag not auto-delete.
- **Alternatives**: Unvalidated strings (rejected — violates Golden Rule B); computed RetainUntil via cron (rejected — IsExpired is query-time derived).
