# Feature Specification: Document Management

**Feature Branch**: `005-document-management`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "SPEC-005 — Document Management **Bounded Context**: BC-05 Documents (Core) · **Depends on**: SPEC-003 (project/work item linkage), SPEC-002 (classification-aware authorization) ## Objective Implement enterprise document management where documents are first-class domain objects with classification, immutable versions, and an audited access model (Constitution Principle IX). ## Requirements **R1 — Document aggregate**: Identity, name, classification (`Public/Internal/Confidential/Restricted/HighlyRestricted` + organization-defined extensions), security classification, owner, organization/tenant, project/work-item links, current version pointer, MIME type, size, hash, status, lifecycle, provenance, retention, access history. **R2 — Immutable versions**: `DocumentVersion` (v1, v2, …) is immutable once published. Corrections create a new version. Each version carries content hash, metadata snapshot, and publication actor/time. Deletion is a lifecycle action (soft, audited), never a row erase. **R3 — Extensible metadata**: author, department, project, tags, document type, effective/expiration dates, source, confidentiality, retention, custom metadata bag — modeled as a value object on the version (snapshot semantics). **R4 — Access evaluation**: Every read/download is evaluated against Golden Rule A plus classification: user, role, org, subtree, project membership, classification, explicit grants. Denials are audited. Document access history is retained. **R5 — Upload pipeline (asynchronous, outbox-driven)**: `Upload → Validation → Virus/Security Scan → Metadata → Classification → Storage → Indexing`. Each stage is a resumable job state (`Enumeration`); failures are explicit and retryable. No stage blocks the HTTP request after upload acceptance. **R6 — Storage**: Binary content goes to object storage (selection via ADR), referenced by hash; the database stores metadata only. Documents at rest are protected per SPEC-012. ## Domain Model **Aggregates** - `Document` (root: `DocumentId`) — Events: `DocumentUploaded`, `DocumentClassified`, `DocumentAccessed`, `DocumentAccessDenied`, `DocumentDeleted`, `DocumentApproved`. - `DocumentVersion` (root: `DocumentVersionId`) — Events: `DocumentVersionPublished`, `DocumentVersionSuperseded`. - `DocumentProcessingJob` (root: `DocumentProcessingJobId`) — Event: `DocumentProcessingStageCompleted`, `DocumentProcessingFailed`. **Value Objects**: `Classification`, `ContentHash`, `MimeType`, `RetentionPolicy`, `DocumentStatus` (Enumeration + lifecycle), `ProcessingStage` (Enumeration), `MetadataSnapshot`. **Domain services**: `IDocumentAccessPolicy` (Golden Rule A + classification), `IClassificationPolicy` (default + org extensions, versioned rules). ## Application Layer (representative) - `UploadDocument`, `PublishDocumentVersion`, `ClassifyDocument`, `ApproveDocument`, `RetryProcessingStage`, `DeleteDocument`. - Queries: `GetDocument(id)` (authorization-filtered), `ListDocumentVersions`, `GetAccessHistory(id)` (auditor/owner scoped). ## Acceptance Criteria - Given a valid upload, When accepted, Then a `Document` + `DocumentVersion` exist, storage holds the binary by hash, and processing jobs are queued via outbox — the HTTP request did not run the pipeline. - Given a published version, When any correction is requested, Then a new version is created; the old one is retrievable and traceable, never mutated. - Given a user outside the subtree/membership/grants, When they request a protected document, Then access is denied and audited, and no binary is served. - Given a virus-scan failure, When the stage retries or fails permanently, Then the job state is explicit and observable (no half-classified documents). - Given classification rules change, When new documents classify, Then the rule version used is recorded. - Given an auditor query, When access history is requested, Then it returns reads, denials, and downloads with actors and timestamps."

**Bounded Context**: BC-05 Documents (Core) — Depends on SPEC-003 (project/work item linkage), SPEC-002 (classification-aware authorization, Golden Rule A + hierarchy), SPEC-012 (storage encryption at rest)

## Clarifications

### Session 2026-09-01

- Q: ¿Debe el sistema impedir la lectura/descarga de un documento que aún no ha sido marcado como seguro tras el escaneo antivirus? → A: Sí — todo documento/versión almacenado en el contenedor debe ser escaneado por antivirus y marcado como seguro; ningún contenedor puede servir lectura/descarga si la versión no está marcada como segura (bloqueo por defecto, incluso con permisos Golden Rule A suficientes; aplica por versión; infectado/pending/stale deniegan y auditan).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Upload document with async outbox pipeline (Priority: P1)

As a document owner, I want to upload a file so that a `Document` and initial `DocumentVersion` are created immediately, the binary is stored by content hash in object storage, and the multi-stage processing pipeline is queued via transactional outbox without blocking the HTTP request, so that upload is fast and resumable.

**Why this priority**: Core MVP — without upload acceptance + async pipeline, no document exists to version, classify, or access. Validates R1/R5/R6 and the BuildingBlocks outbox contract. P1 because every other story depends on documents existing.

**Independent Test**: Can be fully tested by POST `UploadDocument` (name=contract.pdf, mime=application/pdf, size=1.2MB, projectId, classification hint) → HTTP 202 returns `documentId`+`versionId` in <500ms with `status=Uploaded`; querying `GetDocument(id)` shows `Document` + `DocumentVersion v1` with `ContentHash`, `MimeType`, `size`, `currentVersionPointer=v1`; object storage contains blob keyed by hash; `DocumentProcessingJob` row exists with `stage=Validation` pending via outbox; no pipeline stage executed synchronously in the HTTP handler.

**Acceptance Scenarios**:

1. **Given** a valid upload (allowed MIME, size within limit, authenticated owner, tenant, optional project/workItem link), **When** `UploadDocument` is accepted, **Then** a `Document` (`DocumentUploaded`) and `DocumentVersion v1` (`DocumentVersionPublished` not yet — or `Draft` → `Published` after Validation) are persisted in same transaction as outbox messages, object storage holds the binary referenced by `ContentHash`, a `DocumentProcessingJob` with `ProcessingStage.Upload` completed and next stage `Validation` queued is created, and the HTTP response did not execute `VirusScan`/`Classification`/`Indexing`.
2. **Given** an upload with disallowed MIME or size exceeding policy, **When** `UploadDocument` is invoked, **Then** it returns `Error.Validation` with field errors, no `Document` is persisted, no blob is stored, and no job is queued.
3. **Given** a successful upload, **When** `ListDocumentVersions(documentId)` is queried, **Then** it returns v1 with `contentHash`, `metadataSnapshot` (author/department/project/tags/type/dates/source/confidentiality/retention/custom bag), `publishedAt`, `publishedBy`, `mimeType`, `size`.
4. **Given** concurrent uploads of identical content (same bytes), **When** both complete, **Then** both documents reference the same `ContentHash` (deduplicated blob) but have distinct `DocumentId`, and storage contains one blob.

### User Story 2 - Immutable versions and lifecycle (corrections never mutate) (Priority: P1)

As an owner or editor, I want every correction to create a new immutable `DocumentVersion` (v1, v2, …) with its own hash + metadata snapshot + publication actor/time, leaving prior versions retrievable and traceable, and deletion to be a soft audited lifecycle transition, so that history is tamper-evident.

**Why this priority**: Directly implements Principle IX and R2 — immutability is the primary data-integrity invariant. P1 alongside US1; without it documents become mutable files.

**Independent Test**: Can be fully tested by uploading v1 → `PublishDocumentVersion(v1)` → verify `DocumentVersionPublished` and `currentVersionPointer=v1`; then `PublishDocumentVersion(documentId, newBytes, updatedMetadata)` → v2 created with new `ContentHash`, `MetadataSnapshot`, `publishedAt/By`, `DocumentVersionSuperseded` emitted for v1, `currentVersionPointer=v2`; fetching `GetDocumentVersion(documentId, 1)` still returns original hash/metadata unchanged; attempting to mutate v1 via repository returns error or no-op.

**Acceptance Scenarios**:

1. **Given** a published version v1, **When** any correction is requested (new bytes or metadata change) via `PublishDocumentVersion`, **Then** a new `DocumentVersion v2` is created (append, never overwrite), v1 remains retrievable via `ListDocumentVersions` with its original `contentHash`, `metadataSnapshot`, `publishedAt/By`, and `DocumentVersionSupse
rseded(v1)` is emitted; `Document.currentVersionPointer` advances to v2 and `DocumentVersionPublished(v2)` is emitted.
2. **Given** published v1, **When** a direct mutation of v1 fields is attempted (e.g., setting `hash` or `metadata` on the persisted entity), **Then** the domain invariant `VersionIsImmutableOncePublished` rejects with `Error.BusinessRule` and persistence is unchanged (verified by reload).
3. **Given** a document, **When** `DeleteDocument(documentId, actor)` is called, **Then** no row is erased; `DocumentStatus` transitions to `Deleted` (or `Archived`→`Deleted` per lifecycle), `DocumentDeleted` event is emitted via outbox, provenance/retention fields remain, access to binary is denied going forward except for auditors, and the delete is audited with actor+timestamp.
4. **Given** a document with v1..v3, **When** `GetDocument(id)` is called, **Then** it returns current version pointer v3 while `ListDocumentVersions` returns all three with hashes and publication actors/times in order.

### User Story 3 - Classification-aware access evaluation and audited denials (Priority: P1)

As a security officer, I want every read/download evaluated by `IDocumentAccessPolicy` against Golden Rule A plus classification (user, role, org, subtree, project membership, classification, explicit grants), with denials audited and access history retained, so that `Restricted`/`HighlyRestricted` documents are never served to unauthorized actors.

**Why this priority**: Satisfies Principles VII, VIII, IX, XIX and R4 — without this, classification is cosmetic. P1 security invariant; all read paths must enforce it.

**Independent Test**: Can be fully tested by seeding: document `Confidential` owned by Alice in Tenant T, linked to Project P where Bob is not a member and not in owner's subtree and has no explicit grant → `GetDocument(id)` as Bob returns `Error.Forbidden` (generic message), no binary is served, `DocumentAccessDenied` is appended to access history and audit outbox, and `GetAccessHistory(documentId)` as Alice (owner) or auditor shows the denial with `actor=Bob`, `timestamp`, `action=Read`, `classification=Confidential`, `reason=NotInSubtreeOrMembership`.

**Acceptance Scenarios**:

1. **Given** a user outside subtree/membership/grants requesting a protected document, **When** `GetDocument(id)` or download is invoked, **Then** access is denied with `Error.Forbidden`, `DocumentAccessDenied` is emitted and persisted as `DocumentAccessEntry` (denial), no binary bytes are returned, and the denial appears in `GetAccessHistory`.
2. **Given** an authorized user (owner, or subtree manager, or project member with sufficient classification clearance, or explicit grant), **When** they request a `Safe` (`IsSafe=true`) document, **Then** `DocumentAccessed` is emitted, an access history entry `Read`/`Download` with actor/timestamp is appended, and the binary (or presigned URL) is returned.
3. **Given** a document with `HighlyRestricted`, **When** every actor type from the SPEC-013 security matrix (owner, same-org peer, cross-org, subtree subordinate, explicit grant holder, auditor, anonymous) requests it, **Then** the allow/deny matrix matches the policy fixture (only owner+explicit grant+chain-cleared managers) and every denial is audited.
4. **Given** organization-defined classification extensions (e.g., `TopSecretFinance`), **When** a document carries that classification via `IClassificationPolicy` (versioned rules), **Then** `IDocumentAccessPolicy` evaluates it using the same Golden Rule A + extension rule version recorded on the document, and access history records the classification value used.
5. **Given** an otherwise authorized user requesting a document cuya versión no está marcada como segura (`IsSafe=false`, `ScanStatus=Pending|Infected`), **When** `GetDocument(id)` o download es invocado, **Then** access is denied with `Error.Forbidden` + `DocumentAccessDenied(reason=NotSafe)`, no binary/presigned URL es servido desde el contenedor, y la denegación aparece en `GetAccessHistory` aunque Golden Rule A/clasificación/grants estén satisfechos — hasta que `VirusScan` marque `IsSafe=true`.

### User Story 4 - Resumable processing job with explicit retryable failures (Priority: P2)

As an operator, I want the upload pipeline `Upload → Validation → Virus/Security Scan → Metadata → Classification → Storage → Indexing` modeled as a `DocumentProcessingJob` with `ProcessingStage` Enumeration and per-stage status (`Pending|InProgress|Succeeded|FailedRetryable|FailedPermanent`), so that a virus-scan failure is explicit, retryable via `RetryProcessingStage`, and never leaves a half-classified document observable as `Available`.

**Why this priority**: Implements R5 async/resumable invariant and constitution XVII. P2 after core ownership/versioning/auth because it defines operational correctness of the background path.

**Independent Test**: Can be fully tested by uploading → stubbing virus-scan to return `infected` → assert job stage `VirusScan=FailedRetryable` with `DocumentProcessingFailed` event, `DocumentStatus` remains `Processing` (not `Available`), `GetDocument` still shows `indexingState=NotIndexed`; then `RetryProcessingStage(jobId, VirusScan)` with clean bytes → stage advances to `Succeeded`, job proceeds to `Metadata`→`Classification`→`Storage`→`Indexing`, each emitting `DocumentProcessingStageCompleted`.

**Acceptance Scenarios**:

1. **Given** a virus-scan failure (stub returns `infected` or scanner unavailable), **When** the `VirusScan` stage handler runs, **Then** the job transitions to `FailedRetryable` (or `FailedPermanent` if policy says max retries exceeded), `DocumentVersion.IsSafe` permanece `false` (`ScanStatus=Infected|Pending`), `DocumentProcessingFailed(stage=VirusScan, reason, retryable)` is emitted via outbox, `DocumentStatus` does NOT advance to `Available`/`Indexed`, ningún contenedor sirve el binario, y el job state es observable via query.
2. **Given** a job in `FailedRetryable` at any stage, **When** `RetryProcessingStage(jobId, stage)` is called by an authorized operator, **Then** the stage re-executes idempotently; on success of `VirusScan` marca `IsSafe=true`/`ScanStatus=Safe` + `ScannedAt/By`, emite `DocumentProcessingStageCompleted` y avanza a `Metadata`→`Classification`→`Storage`→`Indexing`, on repeat failure stays failed con `attemptCount`/`lastError` actualizado y sin habilitar lectura.
3. **Given** a document mid-pipeline, **When** `GetDocument(id)` is queried, **Then** `processingStage`, `isSafe`/`scanStatus` y `indexingState` son visibles y ningún consumidor ve `Available` ni recibe binario hasta que `VirusScan` haya marcado `IsSafe=true` y `Classification`+`Storage` hayan sucedido (no half-classified, no lectura de no-seguro).
4. **Given** classification rules change after a document is enqueued, **When** the `Classification` stage eventually runs, **Then** it resolves via `IClassificationPolicy` at execution time, records the `ruleVersion` used on the `Document`/`DocumentVersion`, y emite `DocumentClassified(classification, ruleVersion)` — siempre después de `IsSafe=true`.

### User Story 5 - Auditor access history and approver flow (Priority: P2)

As an auditor (or document owner), I want to query `GetAccessHistory(documentId)` to retrieve reads, denials, and downloads with actors and timestamps, and as an approver to run `ApproveDocument` with lifecycle guard, so that access is traceable and approval gates are enforced.

**Why this priority**: Satisfies VIII/IX/XIX plus the acceptance criterion "auditor query returns reads, denials, downloads". Also covers `DocumentApproved` lifecycle. P2 but independent of pipeline retries.

**Independent Test**: Can be fully tested by performing: owner reads, unauthorized Bob denied, owner downloads, then `GetAccessHistory(documentId)` as auditor → returns 3 entries with `actor`, `action(Read/Download/Denied)`, `timestamp`, `classification`, ordered by time; verify non-auditor/non-owner caller gets `Forbidden`. Also test `ApproveDocument(documentId, actor)` transitions `PendingApproval→Approved` and emits `DocumentApproved`.

**Acceptance Scenarios**:

1. **Given** a document with 2 successful reads, 1 download, and 2 denials, **When** `GetAccessHistory(documentId)` is called by an auditor or owner (SPEC-002 auditor/owner scope), **Then** all 5 entries are returned with `actorId`, `action`, `timestamp`, `classification`, `grantedOrDenied`, ordered chronologically, and `GetDocument` callers without auditor/owner role receive `Error.Forbidden`.
2. **Given** a document awaiting approval, **When** `ApproveDocument(documentId, approver)` is called by a user satisfying `IDocumentAccessPolicy` approve permission (role+subtree+ownership), **Then** `DocumentStatus` transitions per lifecycle (e.g., `Classified→Approved→Available`), `DocumentApproved` is emitted via outbox with `approver`+`timestamp`, and a subsequent `GetDocument` shows `status=Approved`.
3. **Given** a document already `Approved` or `Deleted`, **When** a second `ApproveDocument` is attempted, **Then** it is rejected with `Error.BusinessRule` (illegal lifecycle transition) and no duplicate event is emitted.
4. **Given** classification rule version `v3` was used to classify a document, **When** an auditor inspects the document, **Then** `ruleVersion=v3` is visible on `Document` and `DocumentVersion` and survives subsequent rule changes (new documents use `v4` but old record stays `v3`).

### Edge Cases

- What happens when the upload carries a virus and the scanner is down vs. infected? Both map to `FailedRetryable` with distinct `reason` (`ScannerUnavailable` vs `Infected`); infected content never reaches `Storage`; retry after scanner recovery or clean re-upload is the only path; `FailedPermanent` after `maxAttempts` (default 3) requires operator re-upload.
- What happens when two versions claim the same `ContentHash`? Deduplication is allowed — versions may share a hash if bytes identical but metadata snapshots still differ; storage does not duplicate bytes.
- What happens when an organization defines an unknown classification extension not in default set? `IClassificationPolicy` validates against versioned org rule set; unknown value returns `Error.Validation` at upload/classify time; default set `{Public, Internal, Confidential, Restricted, HighlyRestricted}` is always accepted.
- What happens when a document is linked to both a project and a work item but the caller lacks project membership yet is in owner subtree? `IDocumentAccessPolicy` grants access (OR over subtree, membership, explicit grant) — subtree alone suffices if classification clearance passes.
- What happens when `GetAccessHistory` is called by a non-auditor/non-owner? Returns `Error.Forbidden` with audited `DocumentAccessDenied` for that history query itself.
- What happens when object storage write fails mid-pipeline? `Storage` stage marks `FailedRetryable`, preserves idempotency key `ContentHash`; retry does not create duplicate blobs; DB metadata remains unindexed.
- What happens when retention expires? `RetentionPolicy` evaluation (effective/expiration dates) does not auto-delete; it flags `RetentionExpired` status transition which requires explicit audited `DeleteDocument` or `Archive` lifecycle action.
- What happens when concurrent `PublishDocumentVersion` requests race? Optimistic concurrency on `Document.RowVersion` — second writer receives `Error.Concurrency`; no version is lost, caller retries with fresh read.
- What happens when metadata `custom bag` contains sensitive keys? Custom entries are part of `MetadataSnapshot` but access-filtered the same as the document (no separate clearance); validation rejects keys longer than 64 chars or values > 2KB.
- What happens when tenant header is missing or cross-tenant access attempted? All commands/queries require `TenantContext`; cross-tenant document id returns `NotFound` (not `Forbidden`) to avoid enumeration, and the attempt is audited.
- What happens when a version is not yet marked as safe (`IsSafe=false`, `ScanStatus=Pending|Infected`)? `GetDocument`/`Download`/`ListDocumentVersions` deniegan lectura de binario/URL con `Error.Forbidden` + `DocumentAccessDenied(reason=NotSafe)` aunque el actor cumpla Golden Rule A/clasificación/grants; solo metadata mínima (`id`, `status=Processing`, `isSafe=false`) es visible según política; el retry exitoso de `VirusScan` marca `IsSafe=true` y habilita lectura.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST provide `Document` as `AggregateRoot<DocumentId>` (`StronglyTypedId`) with fields: `Name`, `Classification` (VO), `OwnerId`, `OrganizationId`/`TenantId`, `ProjectId` (optional), `WorkItemId` (optional), `CurrentVersionId` pointer, `MimeType` (VO), `Size` (bytes, long), `ContentHash` (VO SHA-256 hex), `DocumentStatus` (Enumeration + lifecycle), provenance (`Source`, `CreatedAt/By`), `RetentionPolicy` (VO), and `AccessHistory` collection (append-only). Every state change MUST emit domain events via transactional outbox.
- **FR-002**: `Classification` MUST be a ValueObject encompassing default levels `Public | Internal | Confidential | Restricted | HighlyRestricted` plus organization-defined extensions resolved through `IClassificationPolicy` (versioned rules). The `ruleVersion` used for classification MUST be persisted on `Document` and `DocumentVersion`. Unknown classifications MUST be rejected with `Error.Validation`.
- **FR-003**: `DocumentVersion` MUST be `AggregateRoot<DocumentVersionId>` with `DocumentId`, `VersionNumber` (v1, v2, … monotonic), `ContentHash`, `MetadataSnapshot` (VO), `MimeType`, `Size`, `PublishedAt`/`PublishedBy`, `IsPublished` flag; once `IsPublished=true`, the version MUST be immutable — any update to hash or snapshot MUST create a new `DocumentVersion` (`DocumentVersionPublished` for new, `DocumentVersionSuperseded` for prior).
- **FR-004**: Deletion MUST be a lifecycle transition (`DocumentDeleted` event), never a row erase: `DocumentStatus` transitions to `Deleted` (valid from `Available | Classified | PendingApproval | ProcessingFailed`) via `DeleteDocument` command, audited with actor+timestamp, and subsequent reads/downloads MUST be denied (except auditors). Soft-deleted rows MUST remain queryable for auditors/history.
- **FR-005**: `MetadataSnapshot` MUST be a ValueObject on `DocumentVersion` with snapshot semantics (copied at publish, never live-joined): `Author`, `Department`, `Project`, `Tags` (set), `DocumentType`, `EffectiveDate`, `ExpirationDate`, `Source`, `Confidentiality`, `RetentionPolicy`, `CustomMetadata` bag (`Dictionary<string,string>` validated: key ≤64 chars, value ≤2KB, ≤50 entries). Snapshot equality MUST be value-equality (all fields).
- **FR-006**: `DocumentStatus` MUST be an `Enumeration` with lifecycle enforcement (e.g., `Draft → Uploaded → Validated → Classified → Indexed → Available → PendingApproval → Approved`, plus `ProcessingFailed`, `Deleted`, `Archived`): illegal transitions MUST return `Error.BusinessRule` via `IBusinessRule`; transitions MUST be audited.
- **FR-007**: System MUST evaluate every read/download via `IDocumentAccessPolicy` implementing Golden Rule A + classification + seguridad sanitaria: factors `user`, `role`, `org/tenant`, `subtree` (via `IManagementHierarchy` from SPEC-002), `project membership` (via SPEC-003 `ProjectMember`), `classification` clearance, `explicit grants` (`DocumentAccess` grant table), **y `IsSafe` (antivirus)**. Un documento/versión NO marcado como seguro tras escaneo (`IsSafe=false`, `ScanStatus≠Safe`) MUST ser denegado incluso si el actor satisface Golden Rule A/clasificación/grants; el contenedor de almacenamiento NO debe servir binario hasta `IsSafe=true`. Policy MUST be pure/testable domain service, deny-by-default.
- **FR-008**: Every denied access MUST emit `DocumentAccessDenied` and append a `DocumentAccessEntry` with `actor`, `action` (`Read`/`Download`), `timestamp`, `classification`, `reason`, and `granted=false`. The binary MUST NOT be served on denial.
- **FR-009**: Every granted access MUST emit `DocumentAccessed` and append a `DocumentAccessEntry` with `actor`, `action`, `timestamp`, `classification`, `granted=true`. Access history MUST be append-only and retained per `RetentionPolicy`.
- **FR-010**: System MUST provide asynchronous upload pipeline as `DocumentProcessingJob` (`AggregateRoot<DocumentProcessingJobId>`) with `DocumentId`, `DocumentVersionId`, `ProcessingStage` Enumeration (`Upload | Validation | VirusScan | Metadata | Classification | Storage | Indexing`), per-stage status `Pending | InProgress | Succeeded | FailedRetryable | FailedPermanent`, `AttemptCount`, `LastError`, `RuleVersion` snapshot, y marcado de seguridad sanitaria. La etapa `VirusScan` MUST escanear el binario en el contenedor vía `ISecurityScanProvider` y al resultar `clean` marcar la versión como segura (`IsSafe=true`, `ScanStatus=Safe`, `ScannedAt`+`ScannedBy`); `infected`/`unavailable` deja `IsSafe=false` y `ScanStatus=Infected|Pending`. Cada stage completion MUST emit `DocumentProcessingStageCompleted`; failure MUST emit `DocumentProcessingFailed(stage, reason, retryable)`; el evento de virus incluye `IsSafe` resultante.
- **FR-011**: Pipeline stages MUST be resumable and retryable: `RetryProcessingStage(jobId, stage)` MUST re-execute the stage idempotently, increment `AttemptCount`, honor `maxAttempts` (default 3) before `FailedPermanent`, and be permissioned via `IDocumentAccessPolicy` (operator/owner). No stage MUST block the HTTP `UploadDocument` request after acceptance (all work after `Upload` is via outbox + background handlers).
- **FR-012**: Pipeline trigger: `UploadDocument` MUST persist `Document` + `DocumentVersion` + `DocumentProcessingJob` + outbox messages in one transaction; background handlers consume outbox/event bus (`BuildingBlocks.EventBus.RabbitMQ`, topic `document.processing.*`) with idempotent processing, manual ack, exponential retries.
- **FR-013**: Classification stage MUST use `IClassificationPolicy` (default + org extensions, versioned rules) to resolve final `Classification` from content/mime/tags/context; the `ruleVersion` used MUST be recorded and emitted in `DocumentClassified(classification, ruleVersion)`. Re-classification via `ClassifyDocument` MUST create a new `DocumentVersion` if content/metadata changes, otherwise update `Document` classification with version bump and audit.
- **FR-014**: Storage: binary content MUST go to object storage (selected via ADR, configured through Aspire; S3-compatible API) keyed by `ContentHash`; database MUST store metadata only (`ContentHash` reference, never blob bytes). Documents at rest MUST be protected per SPEC-012 (encryption, presigned-URL or streaming gateway, no direct bucket listing). Hash verification (SHA-256) MUST occur at `Storage` stage — mismatch returns `FailedRetryable`. **El contenedor NO debe servir lectura directa del blob si la versión asociada no está marcada como segura (`IsSafe=false`); `GetDocument`/`Download` y el gateway de storage MUST verificar `IsSafe` antes de emitir URL/stream y denegar con `Error.Forbidden` + `DocumentAccessDenied(reason=NotSafe)` si no es segura.**
- **FR-015**: System MUST expose commands with `Validator` + `Handler` + `IEndpoint` + `Result<Error>` + transactional outbox via BuildingBlocks (`ISender`, `IPipelineBehavior` Logging/Validation, `IOutboxWriter`): `UploadDocument`, `PublishDocumentVersion`, `ClassifyDocument`, `ApproveDocument`, `RetryProcessingStage`, `DeleteDocument`.
- **FR-016**: System MUST expose queries with authorization-filtered `Result` contracts (never leaking domain entities): `GetDocument(id)` (filtered by `IDocumentAccessPolicy` **incluido `IsSafe`**), `ListDocumentVersions(documentId)` (filtered; cada versión expone `isSafe`/`scanStatus`), `GetAccessHistory(documentId)` (scoped to auditor/owner via `IAuthorizationEvaluator` permission `document.audit.read`). `GetDocument`/`Download` MUST denegar y auditar cuando `IsSafe=false` con `reason=NotSafe` y no servir binario/URL, aunque el actor tenga permisos. Search results MUST be authorization-filtered before return (Principle XV) y solo indexar/retornar versiones seguras.
- **FR-017**: Project/work-item linkage: `Document` MAY link to `ProjectId` and/or `WorkItemId` (SPEC-003); linkage MUST be validated (project/workItem exists, tenant matches) and used as an authorization factor (project membership). Linking/unlinking MUST be via a new `DocumentVersion` if it changes effective metadata.
- **FR-018**: Provenance and retention: `Document` MUST record `Provenance` (source system, upload actor, upload time, original filename) and `RetentionPolicy` (`retainUntil`, `retentionDays`, `legalHold` bool). Retention expiry MUST NOT auto-erase; it surfaces as `RetentionExpired` status and requires explicit lifecycle action.
- **FR-019**: Approval gates: `ApproveDocument(documentId, actor)` MUST enforce lifecycle (`PendingApproval → Approved` valid; `Approved → Deleted` valid; `Deleted → *` invalid) and authorization (approver role + classification clearance), emit `DocumentApproved(approver, timestamp)` via outbox, and transition `DocumentStatus` accordingly.
- **FR-020**: `ContentHash` (VO, SHA-256 hex, 64 chars, lowercase), `MimeType` (VO, validated against allow-list + `application/octet-stream` fallback with warning), `RetentionPolicy` (VO with `retainUntil` computed from `effectiveDate + retentionDays`) MUST all validate at construction and be value-equality comparable.
- **FR-021**: Concurrency: `Document` MUST use optimistic concurrency (`RowVersion`); concurrent `PublishDocumentVersion` or `ClassifyDocument` against stale `RowVersion` MUST return `Error.Concurrency` (HTTP 409) and not create duplicate version numbers.
- **FR-022**: Audit storage for all document events (`DocumentUploaded`, `DocumentClassified`, `DocumentAccessed`, `DocumentAccessDenied`, `DocumentDeleted`, `DocumentApproved`, `DocumentVersionPublished`, `DocumentVersionSuperseded`, `DocumentProcessingStageCompleted`, `DocumentProcessingFailed`) MUST be append-only via outbox; updates MUST never mutate history (Principle VIII).

### Key Entities

- **Document** (AggregateRoot, `DocumentId` StronglyTypedId): `Name`, `Classification` VO, `OwnerId`, `OrganizationId`/`TenantId`, `ProjectId?`, `WorkItemId?`, `CurrentVersionId`, `MimeType` VO, `Size`, `ContentHash` VO, `DocumentStatus` Enumeration, `Provenance` (`Source`, `OriginalFilename`, `CreatedAt/By`), `RetentionPolicy` VO, `RuleVersion` (classification rule version used), **seguridad sanitaria** (`IsSafe` bool derivado de versión actual, `ScanStatus` Enumeration `Pending|Safe|Infected`, `ScannedAt`/`ScannedBy`). Lectura/presigned URL prohibida si `IsSafe=false`. Events: `DocumentUploaded`, `DocumentClassified`, `DocumentAccessed`, `DocumentAccessDenied`, `DocumentDeleted`, `DocumentApproved`, `DocumentMarkedSafe`, `DocumentScanFailed`.
- **DocumentVersion** (AggregateRoot, `DocumentVersionId`): `DocumentId`, `VersionNumber` (int, 1..n), `ContentHash` VO, `MetadataSnapshot` VO, `MimeType`, `Size`, `PublishedAt/By`, `IsPublished` bool, `RuleVersion`, **`IsSafe` bool (false por defecto hasta VirusScan clean), `ScanStatus` Enumeration (`Pending|Safe|Infected|Unavailable`), `ScannedAt`/`ScannedBy`**. Immutable once `IsPublished=true` excepto transición `Pending→Safe/Infected` vía `MarkSafe`/`MarkInfected` (audited, idempotent). Events: `DocumentVersionPublished`, `DocumentVersionSuperseded`, `DocumentVersionMarkedSafe`, `DocumentVersionScanFailed`.
- **DocumentProcessingJob** (AggregateRoot, `DocumentProcessingJobId`): `DocumentId`, `DocumentVersionId`, `CurrentStage` (`ProcessingStage` Enumeration), per-stage statuses map, `AttemptCount`, `LastError`, `RuleVersion`, `CreatedAt`, `UpdatedAt`. Events: `DocumentProcessingStageCompleted(stage)`, `DocumentProcessingFailed(stage, reason, retryable)`.
- **MetadataSnapshot** (ValueObject, snapshot on version): `Author`, `Department`, `Project`, `Tags` (IReadOnlySet<string>), `DocumentType`, `EffectiveDate?`, `ExpirationDate?`, `Source`, `Confidentiality`, `RetentionPolicy`, `CustomMetadata` (`IReadOnlyDictionary<string,string>` validated). Value-equality.
- **Classification** (ValueObject): `Level` (`Public|Internal|Confidential|Restricted|HighlyRestricted` + org extensions), `RuleVersion` (int/string), validated via `IClassificationPolicy`. Ordered sensitivity for access comparison.
- **ContentHash** (ValueObject): SHA-256 hex string, 64 lowercase chars, computed at upload/storage stages, deduplication key for object storage.
- **MimeType** (ValueObject): `Value` (e.g., `application/pdf`), `Extension` derived, allow-list validated.
- **RetentionPolicy** (ValueObject): `RetainUntil?` (`DateTimeOffset?`), `RetentionDays?`, `LegalHold` bool, computed `IsExpired`.
- **DocumentStatus** (Enumeration + lifecycle): `Draft`, `Uploaded`, `Validated`, `Classified`, `Indexed`, `Available`, `PendingApproval`, `Approved`, `ProcessingFailed`, `Archived`, `Deleted`, `RetentionExpired` — with allowed-transition matrix enforced by `IBusinessRule`.
- **ProcessingStage** (Enumeration): `Upload`, `Validation`, `VirusScan`, `Metadata`, `Classification`, `Storage`, `Indexing` — each with `Pending|InProgress|Succeeded|FailedRetryable|FailedPermanent`.
- **DocumentAccessEntry** (Entity, append-only): `DocumentId`, `ActorId`, `Action` (`Read|Download|Denied`), `Timestamp`, `Classification`, `Granted` bool, `Reason` (incluye `NotSafe` cuando `IsSafe=false`). Backing `GetAccessHistory`.
- **Domain Services**: `IDocumentAccessPolicy` (Golden Rule A + classification matrix + `IsSafe` check, deny-by-default, pure — `IsSafe=false` deniega antes de evaluar clasificación), `IClassificationPolicy` (default + org extensions, versioned rules, `Classify(context) → (Classification, ruleVersion)`), `IAntivirusSafetyPolicy` (or part of `IDocumentAccessPolicy`) que enforza `IsSafe` en storage gateway.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Given a valid upload (allowed MIME, within size), when `UploadDocument` is accepted, a `Document` + `DocumentVersion v1` exist with correct `ContentHash`/`MimeType`/`size`/`currentVersionPointer`, the binary is in object storage keyed by hash, a `DocumentProcessingJob` is queued via outbox, and the HTTP request duration is under 500ms with no pipeline stage executed synchronously — verified by timing the handler and asserting zero scan/classify invocations in-request.
- **SC-002**: Given a published v1, when any correction is requested via `PublishDocumentVersion`, a new v2 is created with new `ContentHash`/`MetadataSnapshot`/`publishedAt/By`, v1 remains retrievable unchanged via `ListDocumentVersions`, `DocumentVersionSuperseded(v1)` was emitted, and a direct mutation attempt on v1 is rejected — verified by reload equality.
- **SC-003**: Given a `Confidential` (or higher) document, when a user outside subtree/membership/grants requests it, access is denied with `Error.Forbidden`, no binary bytes are served, `DocumentAccessDenied` is persisted with actor/timestamp/classification/reason, and `GetAccessHistory` as auditor shows the denial — verified by security matrix fixture covering SPEC-013 actor types × every classification level. **Adicionalmente, un documento/versión no marcado como seguro (`IsSafe=false`) deniega lectura/descarga con `reason=NotSafe` aunque el actor tenga permisos Golden Rule A/clasificación, y no sirve binario/URL desde el contenedor.**
- **SC-004**: Given a virus-scan failure stubbed as `infected` or `ScannerUnavailable`, when the `VirusScan` stage executes, the job state transitions to `FailedRetryable` (or `FailedPermanent` after max attempts), `DocumentVersion.IsSafe` permanece `false` (`ScanStatus=Infected|Pending`), `DocumentProcessingFailed(stage=VirusScan)` is observable, `DocumentStatus` stays `Processing`/`ProcessingFailed` (never `Available`/`Indexed`), no lectura desde contenedor es posible, y retry via `RetryProcessingStage` con `clean` marca `IsSafe=true`/`ScanStatus=Safe` y avanza el pipeline — verified by pipeline integration test que también verifica que `GetDocument`/`Download` antes de `IsSafe=true` deniega con `NotSafe`.
- **SC-005**: Given classification rules at version v3 classifying a document, when rules advance to v4 and a new document is classified, the old document still records `ruleVersion=v3` while the new records `v4`, each visible via `GetDocument` — verified by versioned policy fixture.
- **SC-006**: Given a document with mixed access history (reads, denials, downloads), when `GetAccessHistory(documentId)` is called by an auditor/owner, it returns all entries with `actor`, `action`, `timestamp`, `classification`, `granted` in chronological order; a non-auditor/non-owner caller receives `Error.Forbidden` — verified by history fixture.
- **SC-007**: Given an approval gate, when `ApproveDocument` is called by an authorized approver, `DocumentStatus` transitions `PendingApproval→Approved` and `DocumentApproved(approver, timestamp)` is emitted; illegal transitions (e.g., `Approved→Available` or `Deleted→Approved`) are rejected with `Error.BusinessRule` — verified by lifecycle transition matrix tests.
- **SC-008**: Binary storage contains metadata only in the database (no blob bytes in DB), object storage holds blobs keyed by `ContentHash` with at-rest protection per SPEC-012, and hash verification at `Storage` stage rejects mismatched content with `FailedRetryable` — verified by storage contract test asserting no `byte[]` column and hash mismatch scenario.

## Assumptions

- `IManagementHierarchy`/`IAuthorizationEvaluator` and `TenantContext` (SPEC-002) are available as Shared Kernel; until ready, tests use in-memory stubs per BuildingBlocks `Specification<T>` patterns. Permission names consumed: `document.read`, `document.download`, `document.upload`, `document.approve`, `document.audit.read`, `document.processing.retry`.
- `oroidentityserver` OIDC identity provides `sub` (Owner/Actor) and `tenant_id`; every command/query carries `actor`+`tenant`; anonymous access is always denied.
- Object storage selection is per ADR (S3-compatible) and wired via Aspire resource `AddAwsS3`/`AddMinio` or equivalent; presigned URLs or streaming gateway are used for downloads — direct bucket enumeration is prohibited. Encryption at rest per SPEC-012.
- Virus/security scan provider is abstracted (`ISecurityScanProvider`); in development/tests a stub returning `clean|infected|unavailable` is injected; production wire-up is per ADR.
- `IClassificationPolicy` versioned rules are stored as versioned rows (effectiveFrom, ruleSetJson); `ruleVersion` is an opaque version string/int (e.g., `v3`) stamped on each document/version at classification time.
- Default processing `maxAttempts=3` per stage with exponential backoff via BuildingBlocks EventBus; `FailedPermanent` requires manual `RetryProcessingStage` or re-upload.
- `ProjectId`/`WorkItemId` linkage validation calls SPEC-003 read models (existence + tenant match) via Shared Kernel; if SPEC-003 not yet available, validation uses existence stub.
- File constraints: default allowed MIME allow-list + `maxSize` per classification (e.g., 100MB default, configurable per org); virus scan size limit enforced before scan.
- Deduplication: same `ContentHash` blobs are not duplicated in storage; logical documents remain distinct even if they share a hash.
- Audit/access history retention follows `RetentionPolicy.legalHold` semantics — `Deleted` documents' history is retained; hard purge, if ever, is a separate governance flow out of scope.
- Notifications for `DocumentApproved`/`DocumentProcessingFailed` are published as integration events consumed by SPEC-008; this spec only emits via outbox.
- Indexing stage wires to search BC (BC-07) via integration event `DocumentIndexed`; authorization filtering for search is enforced by BC-07 consuming `Classification` + `DocumentAccess` snapshot.
- Optimistic concurrency via `RowVersion` (byte[]/xmin) on `Document`; `DocumentVersion` is append-only with no in-place updates after publish.

## Dependencies & Traceability

- **Depends on**: SPEC-003 Projects & Work Management — `Project`, `WorkItem`, `ProjectMember`, `WorkItemStatusChanged`/`Completed` events, linkage validation; SPEC-002 Identity/Organization — `IManagementHierarchy`, `IAuthorizationEvaluator`, `TenantContext`, `User`/`Role`/`OrganizationUnit`, audit outbox pattern; SPEC-012 Storage Encryption — at-rest protection contract; SPEC-013 Security Matrix — classification × actor authorization matrix for `IDocumentAccessPolicy` tests.
- **Enables**: BC-07 Search/Indexing (consumes `DocumentIndexed` + `Classification` + `MetadataSnapshot`), BC-08 AI/LLM Processing (consumes `Document`/`DocumentVersion` + `DocumentAvailable`), BC-10 Audit/Monitoring (consumes all document audit events), SPEC-008 Notifications.
- **Constitution**: Principles VIII (append-only audit), IX (first-class documents, immutable versions), XV (tenant-aware), XIX (deny-by-default, protected storage), VI (rules in domain), VII (hierarchical + Golden Rule A), XVII (async outbox), XVI (contracts), V (BC-05 module), XX/XXI (testability + TDD/DDD/Vertical Slices), XXII (skills govern). §Document Architecture, §Document Lifecycle (`Uploaded→Validated→Classified→Extracted→Indexed→Available`), §Versioning, Golden Rule B (upload input validation).
- **ADRs required**: Object storage provider selection (ADR-005-01), virus/scan provider (ADR-005-02), indexing strategy (deferred to BC-07).

## Out of Scope

- Full-text extraction/OCR and embedding generation beyond `Metadata` stage stub — owned by BC-08 AI/LLM Processing; this spec provides `Metadata`→`Indexing` hooks and provenance only.
- Search querying and ranking across documents — owned by BC-07 Search/Indexing (this spec only emits `DocumentIndexed` and stores `MetadataSnapshot`).
- Hard physical deletion/purge of blobs and GC of deduplicated storage — governance workflow beyond soft `Deleted` lifecycle.
- Real-time push/WebSocket for processing job progress — poll/query via `GetDocument` job status only.
- Cross-tenant document sharing — explicitly denied; tenant isolation is non-negotiable (Principle XV).
