# Research: Foundation and Architecture

**Feature**: 002-foundation-architecture | **Date**: 2026-08-31 | **Status**: Complete

No `NEEDS CLARIFICATION` markers were present in Technical Context after the FR-010 amendment; the four decisions below resolve the only implementation-choice points that would otherwise be open for Phase 0.

## Decision 1: Platform-CLI Scaffolding (FR-010)

- **Decision**: New .NET projects scaffolded with `dotnet new` templates; Angular frontend with `ng new`. Specifically: `src/Api` via `dotnet new webapi -n Api -o src/Api` (then trimmed to BuildingBlocks conventions: remove WeatherForecast, add `AddServiceDefaults()` + `MapEndpoints()`), each `src/Modules/<Module>/<Module>.Domain|Infrastructure|Application|Contracts` via `dotnet new classlib -n <Module>.<Layer> -o src/Modules/<Module>/<Module>.<Layer>` (then add BuildingBlocks references), `src/Web` via `npx @angular/cli@latest new orokanban-web --directory src/Web --routing --style=scss --skip-git` (then adapt to `minimal-ui-design-system` tokens and `ngrx-signal-store` per SPEC-009). Record exact command + version (`dotnet --version`, `ng version`) in the implementation log / commit message. Aspire augmentation uses `dotnet new aspire-*` where applicable (e.g., service defaults already exist).
- **Rationale**: Satisfies new FR-010 explicitly ("quiero que tambien especifiques que las creaciones de las nuevas aplicacion se hagan por medio de los comandos definidos para cada plataforma ejemplo angular `ng new` dotnet `dotnet new webapi`"). Guarantees reproducible, version-pinned scaffolding and avoids manual-file drift. Aligns with Principle I (reuse templates that encode the canons) and the discovery gate (ADR-001/002 expect standard templates).
- **Alternatives considered**: Manual folder + `Project Sdk="Microsoft.NET.Sdk"` creation (rejected — violates FR-010, not reproducible, misses SDK analyzer defaults), `dotnet new sln` recreation (rejected — `OroKanban.slnx` already exists and would conflict), `npx create-angular` alias (rejected — not the canonical `ng new`).

## Decision 2: AppHost Composition and External Identity Reference

- **Decision**: `OroKanban.AppHost/AppHost.cs` declares `builder.AddPostgres("postgres").AddDatabase("orokanban")`, `builder.AddRabbitMQ("rabbitmq")`, `builder.AddRedis("redis")`, `builder.AddContainer("oroidentityserver", "ghcr.io/ojrojas/oroidentityserver", "latest").WithEndpoint("http", targetPort: 5080).WithEnvironment("ASPNETCORE_URLS", "http://+:5080")` (or `AddConnectionString`-equivalent external resource), then `builder.AddProject<Projects.Api>("api").WithReference(postgres).WithReference(rabbitmq).WithReference(redis).WithReference(oroidentityserver).WithEnvironment("Identity__Authority", oroidentityserver.Resource)`. No identity logic in AppHost or Api beyond JWT bearer validation against the discovery endpoint. `src/BuildingBlocks/BuildingBlocks.ServiceDefaults` satisfies the `OroKanban.ServiceDefaults` role (no duplicate project).
- **Rationale**: Matches discovery finding (bare `Build().Run()` → ADR-001) and constitution IV/II (Aspire as orchestrator, identity external). The Aspire resource model already has external-container support; declaring it makes the identity endpoint discoverable via service discovery and dashboard. Environment-only config for Authority/ClientId/Secret per R5 ensures tenant claim flow works.
- **Alternatives considered**: `AddConnectionString("oroidentityserver")` pointing to a raw URL without container (rejected — loses Podman lifecycle control), self-hosting identity in another `AddProject` (rejected — violates Principle II duplication prohibition), putting Postgres URI in `appsettings.json` directly (rejected — violates Aspire service-discovery and per-environment configurability).

## Decision 3: Persistence Convention and Schema Strategy

- **Decision**: One shared PostgreSQL resource, per-module schema prefix or separate database per module resolved as: **shared database, per-module schema** (`identity`, `organization`, `projects`, …) implemented via `modelBuilder.HasDefaultSchema("<module>")` in each DbContext. Each DbContext inherits `BuildingBlocks.Kernel.Domain` `AppDbContextBase`, calls `modelBuilder.ApplyConfiguration(new OutboxEntityTypeConfiguration())` (from `BuildingBlocks.CQRS` or equivalent namespace), uses Npgsql provider (`Npgsql.EntityFrameworkCore.PostgreSQL` via `Directory.Packages.props`), and defines a `byte[] RowVersion` / `uint xmin` concurrency token on the base aggregate. Migrations are per-module (folder `Infrastructure/Migrations/` per DbContext) using `dotnet ef migrations add` against the module's design-time factory.
- **Rationale**: Discovery shows no DbContext yet; ADR-002 requires a decision that prevents table-name collision while preserving a single Postgres dev resource. Shared-DB/per-schema is the lowest-operational-overhead option that still satisfies bounded-context isolation and allows promotion to separate databases later without changing domain code (only connection-string rebind).
- **Alternatives considered**: One database per module (rejected — 9 databases is heavy for local dev without added isolation benefit now; can graduate to it), single `public` schema with globally unique table names (rejected — unenforceable by tests, collision-prone), `ltree`/`closure table` for hierarchy (rejected — that decision belongs to SPEC-002's hierarchy storage, not this foundation persistence).

## Decision 4: Architecture Test Approach

- **Decision**: `tests/Architecture/` is an `xUnit` project referencing every module `Domain`/`Infrastructure`/`Application`/`Contracts` project plus `Api`. Tests use `NetArchTest.Rules` if available (version from `Directory.Packages.props`) or plain reflection + `Assembly.GetReferencedAssemblies()` if not, to assert: (a) no assembly reference to `MediatR`/`MassTransit`/`AutoMapper`, (b) `Modules.*.Infrastructure` and `Modules.*.Domain` are not referenced across module boundaries (only `Contracts` allowed), (c) every non-abstract `DbContext` in `Modules.*.Infrastructure` derives from `AppDbContextBase` and `OnModelCreating` applies `OutboxEntityTypeConfiguration`, (d) `Directory.Packages.props` contains `Npgsql.EntityFrameworkCore.PostgreSQL` and `Aspire.*` pins. The suite is the "continuous guard" and runs on every build/CI.
- **Rationale**: Directly implements FR-007/R7 and discovery ADR-003. Architecture tests are the only enforcement mechanism for Principles I/V/XXI that survives human review. Reflection-based tests avoid requiring a new heavy dependency if NetArchTest is not yet in the feed; either approach satisfies the contract.
- **Alternatives considered**: Roslyn analyzers only (rejected — require build-time plugin and are harder to cover cross-project references), manual code-review checklist (rejected — not automatable, violates Definition of Done), SonarQube only (rejected — not locally runnable, not branch-blocking).
