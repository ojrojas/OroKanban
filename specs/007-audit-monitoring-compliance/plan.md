# Implementation Plan: Audit, Monitoring and Compliance

**Branch**: `007-audit-monitoring-compliance` | **Date**: 2026-09-01 | **Spec**: [spec.md](spec.md) | **Depends on**: 001-foundation, 002-identity-access-organization, 005-document-management, 006-llm-document-intelligence (all emit audit events)

**Input**: Feature specification — BC-08 Audit (Supporting) + platform monitoring. R1 append-only `AuditEntry` (AuditId, Timestamp, Actor, Action, ResourceType/Id, Organization/Tenant, Result, CorrelationId, client metadata, BeforeAfterSnapshot masked, PreviousHash, hash chaining SHOULD via ADR), R2 event catalog (22+ actions: authz/authn, project/work-item, assignment/status/metric, document lifecycle, permission/grant, hierarchy, AI ops/review, config), R3 emission domain→outbox→integration→audit consumer idempotent with CorrelationId from OTel, R4 audit search (actor/action/resource/project/org/date/result/correlationId, Golden Rule A filtered), R5 operational dashboards (health per dependency, failed requests, background jobs, queue depth, latency, DB errors, auth failures via Aspire dashboard + OTel).

## Summary

Implement BC-08 as the supporting bounded context that owns append-only accountability: every R2 catalog action that succeeds via outbox transaction immediately has one immutable `AuditEntry` persisted by a dedicated `AuditEventConsumer` (idempotent on `EventId`) with actor/resource/result/correlationId/masked snapshot, stored in `audit` schema (`HasDefaultSchema("audit")`, `IsImmutable` no `Update`/`Delete`, `REVOKE` for app role or optional hash-chain `SHA256(PreviousHash||AuditId||Timestamp||Action||Actor)` per ADR-007-01), queried exclusively through authorization-filtered `SearchAuditEntries`/`GetAuditTrail`/`GetOperationTimeline` (Golden Rule A subtree + project + explicit grant + `auditor|manager` before fetch, `IAuditQueryAuthorization` pure + `IAuditMaskingPolicy` for `***`), and operational health/metrics/logs via `AddServiceDefaults()` (`/health` per-dependency `postgres/rabbitmq/redis/ai_provider/vector_store`, `/alive` liveness, Prometheus `http_requests_failed_total`, `job_failed_total`, `rabbitmq_queue_depth`, `http_request_duration_ms` histogram, Serilog OTLP) surfaced in Aspire dashboard (+ OTel backends). All other BCs remain producers; audit never mutates business state.

## Technical Context

**Primary Dependencies**: `BuildingBlocks.Kernel.Domain` (AggregateRoot, StronglyTypedId, Enumeration, ValueObject, IBusinessRule/CheckRule, Specification<T>, Result/Error, IRepository `AddAsync` only for Audit), `BuildingBlocks.CQRS` (ISender, ICommand/IQuery, ICommandHandler/IQueryHandler, IPipelineBehavior — Validation + Logging, IValidator), `BuildingBlocks.EventBus` + `RabbitMQ` (IntegrationEvent, IEventBus `audit.*` topic, `IIntegrationEventHandler`), `BuildingBlocks.ServiceDefaults` (already wired — `AddServiceDefaults()` OTel/Serilog/health/resilience), `BuildingBlocks.Kernel.Infrastructure` (AppDbContextBase, EfRepository, SpecificationEvaluator, OutboxEntityTypeConfiguration, UnitOfWork, OutboxProcessor `SELECT ... FOR UPDATE SKIP LOCKED`), `Npgsql.EntityFrameworkCore.PostgreSQL` + `Microsoft.EntityFrameworkCore` (HasDefaultSchema, jsonb `BeforeAfterSnapshot`, `PreviousHash`/`Hash`), `Microsoft.AspNetCore.Authentication.JwtBearer` (already in Api — provides `sub`/`tenant_id`/roles), `OpenTelemetry` + `Serilog` (OTel `Activity.Baggage` + `AsyncLocal<TenantContext.CorrelationId>` for CorrelationId propagation), `HealthChecks` (`Microsoft.Extensions.Diagnostics.HealthChecks` — per-dependency), `StackExchange.Redis` via Aspire `redis` (optional)

**Storage**: PostgreSQL via Aspire `postgres` — schema `audit` (via `HasDefaultSchema("audit")`). Tables `audit.audit_entries` (`AuditId` PK Guid, `Timestamp` UTC indexed desc + composite `(TenantId, Timestamp desc)`, `ActorId`, `ActorType`, `Action` int FK `AuditAction` Enumeration, `ResourceType` 1..100, `ResourceId` 1..200, `OrganizationId` Guid?, `TenantId` Guid indexed — isolation, `Result` int FK `AuditResult`, `ErrorCode` 1..100, `CorrelationId` Guid indexed — timeline, `IpAddress` 1..45, `UserAgent` max 500, `BeforeJson`/`AfterJson` `jsonb` masked via `IAuditMaskingPolicy`, `PreviousHash` 64 hex? `Hash` 64 hex? if chaining per ADR-007-01, `OrganizationName` snapshot), `audit.audit_consumed_events` (`EventId` PK Guid `UNIQUE`, `ProcessedAt` UTC — idempotency dedup), `outbox_messages` (per `AppDbContextBase`). No `UPDATE`/`DELETE` path compiled — `IRepository<AuditEntry>` exposes only `AddAsync` + `SaveChangesAsync`; DB app role has `REVOKE UPDATE, DELETE ON audit.audit_entries` if no hash chain; if hash chain adopted, chain computed in same transaction with `SELECT ... FOR UPDATE` on tail entry. Outbox per `AppDbContextBase`.

**Testing**: xUnit (`dotnet test`), NetArchTest, Testcontainers for Postgres + RabbitMQ (via `Testcontainers.RabbitMq` if needed, otherwise NSubstitute for `IEventBus`), `NSubstitute` for `IManagementHierarchy`/`IProjectMembership`/`IEventBus` fakes, `Microsoft.AspNetCore.TestHost` for Api auth filtering, `OpenTelemetry` `Activity` baggage for correlation. TDD: unit (masking policy `ApiKey→***`, query authorization composition Golden Rule A, entry immutability — no public setters compiled — via reflection), integration (consumer idempotency duplicate delivery → one entry, search filters `actor+action+resource+project+org+date+result+correlationId` with tenant+subtree pre-filter, correlation propagation `X-Correlation-Id → TenantContext → Activity → DomainEvent → IntegrationEvent → AuditEntry`), security (cross-branch audit search MUST NOT surface other branch entries; `CrossBranchAuditSearchTests` 5 actor types × 2 branches), E2E (distributed document workflow `HTTP→storage→processing→LLM→review` timeline reconstructible via `GetOperationTimeline`).

**Target Platform**: Linux containers via Podman (Aspire dashboard), `oroidentityserver` external container reference already declared in `OroKanban.AppHost/AppHost.cs` (Authority via `Identity__Authority` / `Oidc__Authority`). Api is the single composition host exposing `src/Modules/Audit` endpoints via vertical slices. Web `src/Web` audit timeline/search + health dashboards consume contracts via `minimal-ui-design-system` (flat/elevated) + `ngrx-signal-store`.

**Project Type**: Modular monolith — this feature touches `src/Modules/Audit` (new `AuditEntry` append-only + consumer + queries + health/metrics) as universal consumer; it **produces no domain events** for other BCs (terminal record) but consumes every prior BC's `DomainEvent→IntegrationEvent` (001 foundation, 005 document lifecycle, 006 AI ops). No new business state for other BCs; audit never mutates `Project`/`Document`/`LlmResult`.

**Performance Goals**: `SearchAuditEntries` for 1k entries paginated <300ms p95 (composite index `(TenantId, Timestamp desc)` + `(ResourceType, ResourceId)`); `GetAuditTrail` for single resource 1k entries <300ms p95; `GetOperationTimeline` for correlation 7 entries <100ms p95; audit consumer handles 100 events/sec without duplicate (idempotent dedup via `audit_consumed_events` unique); `GET /health` per-dependency check <500ms p95; `GET /alive` <50ms; background job `OutboxProcessor` poll `SELECT ... FOR UPDATE SKIP LOCKED` <1s batch; audit trail queryable within 2s of business commit.

**Constraints**: Principle I: reuse BuildingBlocks canon — no MediatR/MassTransit/AutoMapper; separate via `minimal-ui-design-system` for dashboards (tokens/elevation) + `ddd-project-planner` for BC-08 context; Principle VI: rules in Domain via `CheckRule`/`IBusinessRule`/`Specification<T>` — `IAuditMaskingPolicy`/`IAuditQueryAuthorization` are pure domain services, not controllers; Principle VIII: append-only audit — `AuditEntry` has no setters, `IRepository` only `AddAsync`, corrections are new entries with `Action=AuditCorrected` (never update), `arch test AuditEntryIsImmutable` enforces zero public mutators; Principle XV: every `Specification<T>` includes `tenant_id`, cross-tenant access returns 404 (not 403) to avoid enumeration; Principle XVII: async via outbox + RabbitMQ, consumer `IHostedService` background with manual ack + exponential retries (at-least-once), idempotent via `EventId` dedup; Principle XVIII: observability mandatory — `AddServiceDefaults()` OTel/Serilog/health must be wired, `CorrelationId` propagated via `Activity.Baggage` + `AsyncLocal<TenantContext.CorrelationId>` + `IOutboxWriter.CorrelationId`; Principle XIX: deny-by-default, least privilege, no secrets in source, `BeforeAfterSnapshot` masked via `IAuditMaskingPolicy` (`ApiKey→***`) before persistence, `Audit:MaskedFields` config extensible; hash chaining vs `REVOKE UPDATE, DELETE` decided per ADR-007-01 (`SHOULD` not `MUST`); alerts via ADR-007-02 (only emit metrics/health, not alerting infra itself).

**Scale/Scope**: 1 aggregate (`AuditEntry`) + 2 Value Objects (`ActorReference`, `ResourceReference`, `BeforeAfterSnapshot`, `AuditResult`) + 2 Enumerations (`AuditAction` 31 values, `AuditResult` enumeration) + 2 domain services (`IAuditMaskingPolicy`, `IAuditQueryAuthorization`) + 1 dedup entity (`AuditConsumedEvent`) + 3 queries + 1 background consumer + health/metrics integration; ~25 new files in `Audit` module; 31 `AuditAction` seeded; no new Aspire resources beyond existing `postgres`/`rabbitmq`/`redis` (audit reuses `postgres` + `rabbitmq` audit topic; dashboards reuse existing Aspire `WithReference`).
